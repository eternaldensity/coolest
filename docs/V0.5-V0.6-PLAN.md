# v0.5 / v0.6 Plan — Contracts, then Programs

> Written 2026-11-01. **Status: v0.5 complete; v0.6 code complete.**
> Body/Mind, items, combat, Veil, contracts, and typed programs are in,
> including Connector remote probes and a scan report. The remaining v0.6
> item is the **human M2 60%/90% success-rate playtest**; host zones/files/
> accounts remain v0.7 candidates.
>
> This plan deliberately keeps the **PDS bridge out of v0.5 and v0.6**.
> The discussion showed ATProto adds *reach*, not new mechanics; local
> contracts and program identity add mechanics. PDS remains a v0.7
> candidate (alongside hosts-as-dungeons), with
> `docs/PDS-BRIDGE-REQUIREMENTS.md` ready.

## Roadmap decision

| Version | Theme | Primary gap closed | ATProto? |
|---|---|---|---|
| **v0.5** | **Contracts & Consequence** | Infinite `Work`; no goals, deadlines, or employer pressure | No |
| **v0.6** | **Programs with Identity** | Generic killer programs; no loadout choice; M2 “choice matters” gate unproven | No |
| v0.7 candidate | PDS Bridge Mode A, or Hosts as Dungeons | Federated mail/board, or zones/files/accounts | Later |

Why this order:

1. **Contracts first** because they connect every system already built:
   Street, items, Deck, Net, Veil, crime, cops, ledger, and mail. They also
   give the board a reason to exist before federation.
2. **Programs second** because the Deck is the game’s differentiator and
   the M2 gate cannot pass while every load is the same generic killer.
3. **PDS third** because federation should transport meaningful offers,
   not paper over a shallow local loop. It also has the largest external
   dependency and failure surface.

## v0.5 — Contracts & Consequence

### Goal

Replace “click Work forever” with a small, finite, consequential contract
board that reuses existing verbs. No ATProto dependency.

### Exit criteria

- A daily board of 3–6 local offers with pay, requirements, deadline,
  employer, and risk.
- `Accept` reserves one offer and creates an active contract.
- One active contract at a time; board refresh and offer expiry are
  visible.
- At least **three** completion paths: component delivery, host hack,
  courier. Bounty can follow if cheap.
- Reward is **escrowed from the employer**, not minted on completion.
- Abandon/expire fails cleanly, with reputation or deposit consequences.
- Illegal contracts file crimes through the existing `report_crime` path.
- HUD/`advise()` shows the active contract and time remaining.
- Save/load, replay hash, fuzz, and headless GUI tests cover the full
  accept → complete/fail loop.
- `client-web` prints a scripted contract tour.
- No ATProto code is required or enabled by this version.

### Data model (proposed)

```rust
enum OfferKind {
    Deliver { item: String, qty: u32 },       // components or inventory item
    Hack { host: HostId, goal: HackGoal },    // breach/exploit/retrieve
    Courier { to: EntityId, tile: Pos },      // arrive + hand off
    Bounty { target: EntityId },              // optional later
}

enum Risk { Legal, Grey, Illegal, Combat }
enum OfferSource { Local, AtUri(String) }     // AtUri reserved, not wired

struct JobOffer {
    id: u64,
    employer: EntityId,
    kind: OfferKind,
    payout_cents: i64,
    deposit_cents: i64,
    requirements: Requirements,               // units, item, record, license
    deadline_tick: u64,
    risk: Risk,
    source: OfferSource,
}

struct Contract {
    offer: u64,
    state: ContractState,                     // Accepted/InProgress/...
    accepted_tick: u64,
    deadline_tick: u64,
    progress: u32,
    escrow_account: u64,
    employer: EntityId,
}
```

World additions:

- `offers: Vec<JobOffer>` / `board_day: u64`
- `contract: Option<Contract>` (one active for v0.5)
- `employer_rep: BTreeMap<u64, i32>`
- all fields `#[serde(default)]`; old saves start with an empty board.
- no `HashMap`, no wall clock, no new sim dependencies.

### Workstreams (one commit per unit)

**5.1 — Contract state + templates**
- New `sim/src/contracts.rs` for `OfferKind`, `Risk`, `JobOffer`,
  `Contract`, `ContractState`, `OfferSource`.
- `data/contracts.yaml` for templates: id, kind, employer role, pay band,
  deadline, requirements, risk, min reputation.
- `World` fields + save defaults; deterministic template selection.
- Tests: old save loads; YAML validation; no duplicate ids.

**5.2 — Deterministic board generation + refresh**
- Generate offers once per game day from templates, district/role, and
  world seed; board shows 3–6.
- Deadline ticks derived from `DAY_TICKS`; no wall clock.
- Refresh/expiry is an `apply` side effect, not a per-frame call.
- Tests: same seed/day → same offers; next day rerolls; expired offers
  disappear.

**5.3 — Accept + escrow**
- `Verb::AcceptOffer { offer: u64 }`.
- Refuse if an active contract exists, offer expired, requirements unmet,
  or employer cannot fund the reward.
- Move employer → escrow account through `Ledger`; deposit from player
  pocket/bank if required.
- Reserve the offer; create `Contract`; set deadline.
- Tests: double-accept refused; ledger stays closed; underfunded offer
  refused without mutation.

**5.4 — Component-delivery completion**
- `Verb::DeliverContract { contract: u64 }` (or `WorkContract`).
- Check the delivery condition against rig stock/inventory, consume it
  atomically, then transfer escrow → player account.
- Reputation +1; contract cleared; event `contract_done`.
- Tests: shortfall refuses; success moves money/items exactly once;
  replay reproduces.

**5.5 — Hack / courier hooks**
- `Hack`: mark progress when the matching `Exploit`/`DeckStrike`/
  `DeckCard` succeeds on the target host; `DeliverContract` claims it.
- `Courier`: mark progress when the player reaches the target tile/NPC;
  `DeliverContract` claims it.
- Illegal completion files `Trespass`/`Theft`/`Attack` via `report_crime`.
- Tests: wrong host/tile does not complete; cops/heat still apply.

**5.6 — Abandon, expiry, reputation**
- `Verb::AbandonContract`.
- On abandon/expiry: return escrow to employer (or city), forfeit player
  deposit, lower employer reputation; no double payout.
- Reputation gates higher-value offers; repeated failures remove offers.
- Tests: abandon/expiry paths; no money duplication; reputation changes
  offer pool.

**5.7 — GUI board + tracker**
- Street board panel: title, employer, pay, requirements, deadline, risk,
  `Accept`.
- Active contract row: objective, time left, `Deliver`, `Abandon`.
- Status/`advise()` prioritizes an expiring contract over generic work.
- Use `horizontal_wrapped`; keep rows short.
- Headless tests: board → accept → deliver → paid; abandon; expiry.

**5.8 — Content + tools + docs**
- 6–8 templates across shopkeeper/office/clan/city employers.
- Add every new verb to `tools/src/lib.rs::fuzz_verb` and bump the range.
- `client-web` scripted contract tour.
- Update PLAYER_GUIDE/HANDOFF; run gate, replay-fuzz, nightly.

### What v0.5 enables

| Mechanic | Gameplay |
|---|---|
| Finite board | Choice and scarcity; no infinite Work grind |
| Accept/active contract | Commitment, deadlines, planning against needs/rent |
| Escrow | Real economy: employer funds, failure forfeits, no free mint |
| Delivery/hack/courier | Board points Net → Deck → Street at a goal |
| Risk/record gates | Legal work needs clean standing/license; illegal work raises heat |
| Reputation | Better offers, clan/corporate work, consequences for failure |
| One active slot | Meaningful tradeoffs rather than hoarding every offer |

### What v0.5 deliberately does not do

- No ATProto records, bridge, or remote offers.
- No player-posted contracts.
- No cross-city escrow.
- No full quest chains/narrative arcs.
- No second `Work` system; `Work` remains day labor.

## v0.6 — Programs with Identity

### Goal

Make the Deck loadout a real choice. Every program should not be the same
generic killer; different kinds should create different plans and
counterplay. This is the M2 “choice matters” milestone.

### Exit criteria

- Seven program kinds: Killer, Shield, Scanner, Cracker, Connector,
  Cloner, Editor.
- `DeckLoad` chooses a kind; max length, CPU cost, damage, and ability
  differ by kind.
- Kind-specific verbs work on the existing host state:
  - Scanner: reveal logs/vulns/trace/private signals.
  - Cracker: multi-turn crack of a firewall/lock.
  - Editor: patch a vuln, scrub a log, overwrite/isolate a tail.
  - Cloner: clone a program to a free cell.
  - Shield: guard/soak; Killer: damage; Connector: remote probe.
- Type synergy: a kind’s affinity interacts with cards/resources, not just
  raw damage.
- Starter loadout can clear the range at the M2 gate rate; changing the
  loadout materially improves the success rate.
- Save defaults: old programs load as Killer; replay/fuzz/nightly green.
- GUI loadout row + kind descriptions + new action buttons; headless tests.

### Data model (proposed)

```rust
enum ProgramKind {
    Killer, Shield, Scanner, Cracker, Connector, Cloner, Editor,
}

struct Program {
    // existing fields...
    #[serde(default)]
    kind: ProgramKind,          // old saves -> Killer
}

struct KindDef {
    kind: ProgramKind,
    max_len: u8,
    cpu_per_seg: u8,
    damage: u8,
    affinity: Affinity,         // card/stat or resource affinity
    ability: Ability,           // Scan/Crack/Patch/Clone/Guard/...
}
```

`data/kinds.yaml` mirrors the code defaults and is validated like jobs,
cards, vulns, and items. `ProgramKind` is serialized with a default so old
snapshots keep working.

### Workstreams (one commit per unit)

**6.1 — ProgramKind + loadout**
- Add `ProgramKind`, `KindDef`, `data/kinds.yaml`, validation.
- Extend `DeckLoad` (or add `DeckLoadAs { kind, x, y }`) so the player
  chooses a kind; keep old generic load as Killer for compatibility.
- CPU/max-len/damage per kind; load refusal when CPU is short.
- Tests: every kind loads; old save defaults; YAML/code cross-check.

**6.2 — Scanner + Cracker**
- `Verb::DeckScan`: reveal logs/vulns/trace and the host’s current
  state; requires a Scanner on the host.
- `Verb::DeckCrack`: multi-turn progress against a firewall/lock; requires
  a Cracker; progress persists in host state; interrupts on program death.
- Tests: scan reveals; crack needs turns; crack refused without Cracker.

**6.3 — Editor + Cloner + overwrite**
- `Verb::DeckPatch`: close a vuln (Editor); `DeckScrub` already exists but
  can be gated by Editor/privilege.
- `Verb::DeckOverwrite`: sever/isolate a tail segment (Editor).
- `Verb::DeckClone`: clone a program to a free cell (Cloner; cost + CPU).
- Tests: patch closes; overwrite isolates; clone inherits owner/mods.

**6.4 — Shield / Killer / Connector**
- Killer: damage baseline; Shield: guard/soak ability (or starts with a
  built-in shield mod); Connector: `DeckConnect` probes a routed host,
  reveals it, and logs the transit (no remote head until zones land).
- Ensure warden/retaliation behavior still makes sense for each kind.
- Tests: kinds survive/die per role; producers unaffected.

**6.5 — Type synergy**
- Define `Affinity` (e.g. Focus/Stability/Clarity, or Loop/Data/Algo) and
  apply a small bonus when a card/producer matches the kind.
- Keep it bounded: +1 damage/effect or +1 yield, never a multiplier that
  makes one kind strictly best.
- Data-driven `kinds.yaml`; tests pin the bonus and the TTK range.
- This is the first thing that reads program *type*; no generic program
  mechanics should remain.

**6.6 — GUI loadout and actions**
- Loadout row: kind buttons with cost/role labels; selected-cell actions
  context-aware (Scan/Crack/Patch/Overwrite/Clone).
- Host panel shows kind, max len, CPU, ability, and affinity.
- Keep rows wrapped; headless tests for each new action.

**6.7 — M2 playable gate + tools**
- Add a balance/soak check: starter loadout infiltration success vs
  changed loadout success (design/12 M2 gate: ~60% first try, ~90% after
  loadout change).
- Add every new verb to `fuzz_verb`; run replay-fuzz + nightly.
- `client-web` scripted deck loadout tour; update docs.

### What v0.6 enables

| Mechanic | Gameplay |
|---|---|
| Loadout choice | Player plans a deck for a host instead of loading generic killers |
| Scanner | Recon becomes a real step: see vulns/logs/trace before committing |
| Cracker | Multi-turn tension and a reason to protect your programs |
| Editor | Get-out-clean play: patch, scrub, overwrite, isolate |
| Cloner | Build a swarm/backup plan; CPU pressure matters |
| Shield/Killer | Real front-line vs support tradeoffs |
| Type synergy | Cards/resources reward matching kind, not one best program |
| M2 gate | “Choice matters” becomes measurable, not aspirational |

### What v0.6 deliberately does not do

- No host zones/files/accounts yet (see v0.7 candidate).
- No full remote-admin allowlist or password rotation.
- No new Net topology/relay work.
- No ATProto/PDS dependency.
- No body-part combat or full skill tree.

## Cross-cutting rules

- One commit per unit; `area: what and why`.
- `./gate.sh` green before every commit; `replay-fuzz` after `apply`/state
  changes; `nightly.sh` after sim evolution/data changes.
- Every new `Verb` goes into `tools/src/lib.rs::fuzz_verb` and bumps the
  roll range.
- New serialized fields are `#[serde(default)]`; never reorder fields.
- Determinism: no clock/network/filesystem in `sim`; board/deadline logic
  uses ticks and seed.
- Data files are validated; code defaults mirror YAML and are pinned by
  tests.
- GUI rows use `horizontal_wrapped`; headless accesskit tests, no
  screenshots.

## Risks

| Risk | Mitigation |
|---|---|
| Contracts become a menu skin | Require accept → active → completion/failure + escrow + deadline; use the “remove Accept and nothing changes” test |
| Escrow duplicates money | Ledger transfer employer → escrow → player; test closed ledger and double-payout |
| One active contract is too restrictive | Start with one; tune to 2 after playtest; keep state/UI simple |
| Deadlines feel punishing | Make deadlines visible, use game days, allow abandon with a known penalty |
| Program kinds are unbalanced | Data-driven `kinds.yaml`; TTK/M2 gate; no multipliers; soak/fuzz |
| Kind abilities need host targets that do not exist yet | Scope v0.6 to existing host state (logs/vulns/firewall/trace/programs); defer zones/files |
| Scope creep into PDS | Explicit non-goal; bridge stays v0.7 |

## Verification and playable gates

v0.5:

- Board → accept → deliver/hack/courier → paid; abandon/expire; save/load;
  replay hash; headless GUI test; `client-web` tour.
- Human gate: complete two contracts (one legal, one illegal) and recover
  from one failure.

v0.6:

- Every kind loads and has a distinct useful action; old saves default to
  Killer; replay/fuzz/nightly green.
- Human gate: clear the range with the starter loadout, then clear it
  faster/more safely after changing the loadout — the M2 “choice matters”
  test.
